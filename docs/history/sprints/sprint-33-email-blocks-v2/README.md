# Sprint 33 — Email blocks v2 (sections, columns, richer blocks)

## Goal

Replace the flat v1 block list with a **Section → Column → Block** document so
emails can lay content side by side, add the blocks self-storage emails actually
need, and turn the block schema and token catalogue into one contract shared by
the validator, renderer, canvas and (in S34) the template assistant.

Today `template_variants.blocks` holds `{version: 1, blocks: [{id, type, params}]}`,
validated by `App\Support\Communications\EmailBlockDocument` (closed set, forward
compatibility by version bump) and rendered by `EmailBlockRenderer`. Every block is
one full-width row. There is no way to put an old rate next to a new rate, an image
next to text, or a two-column footer.

This sprint is the prerequisite for **S34 — Template assistant**. The assistant edits
documents through ops that target a parent (`column_id`, `index`). Building it on the
flat model would mean rewriting the op format and the applier later.

## Design decisions (lock at kickoff)

| # | Decision | Rationale |
|---|---|---|
| B1 | Document v2 has a **fixed hierarchy**: `sections[] → columns[] → blocks[]`. A section is never inside a column; columns are never inside columns. | Outlook renders nested tables inconsistently, and mobile stacking is only predictable at one level. Typed levels let the validator reject illegal nesting without special rules. |
| B2 | Column layouts are **presets only**: `100`, `50_50`, `33_67`, `67_33`, `33_33_33`. Maximum three columns. | Every preset is a layout we have render-tested. Free widths produce layouts nobody tested. |
| B3 | `version: 2` is a **version bump**, not a tolerated variant. The validator accepts v1 and v2 on read; every **write** (draft save, draft creation) stores v2. | Same forward-compat rule as v1 (`EmailBlockDocument` docblock). |
| B4 | **No backfill.** Published v1 variants are never rewritten (invariant 74 and its trigger). A draft created from a v1 published version is upcast to v2 when the draft is created. The renderer renders both versions. | Same stance as S29 V2. Seeders and factories emit v2, so `migrate:fresh` + `demo:seed` gives v2 everywhere. |
| B5 | `raw_html` stays legacy-import only, and only in a `100` section. | Keeps the S13 legacy path; arbitrary HTML inside a column breaks the column table. |
| B6 | **Email channel only.** `DocumentBlockDocument` (contract documents) is untouched this sprint. | PDF layout has different constraints; out of scope. |
| B7 | One **`TokenCatalog`** replaces `SubjectTokenBag::vocabulary()` as the source of the token menu, the publish validator's sample values, and (S34) the assistant. Token availability is derived from the family's `TemplatePurpose`. | Fixes the known drift: publish-validator sample tokens are a hand copy of the bag. |
| B8 | Brand stays in `GeneralSettings`. `email_accent_color` exists; add logo, text colour, background colour and font stack next to it. No separate brand table. | Smallest change that gives the renderer and the assistant a brand to use. |

## Document v2 shape

```json
{
  "version": 2,
  "settings": { "background_color": null },
  "sections": [
    {
      "id": "sec_4f9a1c2e",
      "layout": "50_50",
      "params": { "background_color": "#F7F5F2", "padding": "md", "stack_on_mobile": true },
      "columns": [
        { "id": "col_8b21d0aa", "blocks": [
          { "id": "blk_1e7c9f30", "type": "heading", "params": { "text": "Current rate", "level": 2 } }
        ] },
        { "id": "col_2c6e4b11", "blocks": [
          { "id": "blk_93ad5e02", "type": "heading", "params": { "text": "New rate", "level": 2 } }
        ] }
      ]
    }
  ]
}
```

- Keys follow v1: `params`, not `props`.
- Ids: `sec_` / `col_` / `blk_` + 8 lowercase hex characters, unique across the
  document, stable across moves. Generated by the panel (and in S34 by the API).
- `padding` is a token (`none | sm | md | lg`), not pixels, so the renderer owns spacing.

## Exit criteria

- [ ] An operator builds a rate-increase email by hand with a `50_50` section showing
      old and new rate, and it renders correctly in Outlook 365, Gmail web, Gmail iOS
      and Apple Mail (render matrix in this folder).
- [x] On a phone-width preview, columns stack in order.
- [x] Opening a v1 published template and pressing **Edit** creates a v2 draft that
      looks the same in preview. The published v1 variant is unchanged.
- [x] The token menu, publish validator and preview sample values all come from
      `TokenCatalog`; a debt template offers `contract.balance_owed`, a newsletter
      template does not.
- [x] Undo/redo works for every canvas edit.
- [ ] `migrate:fresh` + `demo:seed` produce v2 templates, and the demo journeys still
      render and send.

## Out of scope

- Anything AI (S34).
- Columns in contract documents (B6).
- Free column widths, nested sections, background images.
- A drag-and-drop page builder beyond what `vue-draggable-plus` already gives the canvas.
- HTML mode changes.
